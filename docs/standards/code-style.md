# Стиль написания кода

## Общие принципы

- Один стиль именования и структуры во всем проекте.
- Простые функции и короткие методы с явной ответственностью.
- Комментарии только там, где без них теряется смысл.

## Язык и оформление

- Докстринги и сообщения об ошибках: на русском.
- Тексты комментариев и рабочая документация в коде: на русском.
- Имена сущностей, полей и функций: консистентные (`snake_case`).
- Не смешивать старые и новые термины в одном модуле.

## Архитектурная дисциплина

- Следовать пути `endpoint -> service -> validators -> crud`.
- Не добавлять временные обходы в endpoint.
- Не держать «мертвый» код после смены контракта.

## PR-чеклист

1. Контракт endpoint ясен и стабилен.
2. Ошибки и коды ответов согласованы.
3. Есть unit/integration тесты поведения.
4. Миграции и модель синхронизированы.
5. Не нарушены security-ограничения (валидации, rate-limit и т.д.).
