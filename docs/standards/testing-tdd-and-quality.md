# Тестирование: TDD и quality-gate

## Обязательные правила

- Работаем по TDD: `Red -> Green -> Refactor`.
- Любая функциональная задача закрывается только после green-тестов.
- Минимальный порог покрытия: `>= 90%`.

## Рабочий цикл TDD

1. Формализовать поведение (вход/выход/ошибки).
2. Написать падающий тест.
3. Реализовать минимальный код до прохождения теста.
4. Сделать рефакторинг без изменения поведения.
5. Повторить цикл для следующего кейса.

## Что тестируем

- Unit: валидаторы, сервисы, CRUD-слой, адаптеры.
- Integration: критичные endpoint-сценарии и коды ошибок.
- Миграции: совместимость схемы и ORM на актуальной ревизии.

## Definition of Done для задачи

- Все новые кейсы покрыты тестами.
- `pytest` проходит локально.
- Порог покрытия `>= 90%` соблюден.
- CI зеленый.
