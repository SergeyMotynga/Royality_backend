# Архитектурный стиль

## Базовый поток

`endpoint -> service -> validators -> crud`

## Зоны ответственности

- `api/endpoints`: HTTP-контракты, коды ответов, зависимости доступа, минимум бизнес-логики.
- `services`: бизнес-сценарии и оркестрация.
- `validators`: переиспользуемые бизнес-валидации и policy-checks.
- `crud`: доступ к БД и простые операции чтения/записи.
- `models`: ORM-сущности.
- `schemas`: Pydantic-контракты request/response.

## Правила

- Endpoint не обращается в CRUD напрямую.
- Service не содержит SQL.
- CRUD не принимает решения бизнес-уровня.
- Любая новая фича добавляется тем же паттерном слоев.
- Public/Admin разделяются роутерами и зависимостями прав доступа.
