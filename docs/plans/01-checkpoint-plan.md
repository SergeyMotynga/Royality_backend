# Чекпоинт-план (зафиксированный фокус)

## Оценка на момент чекпоинта

- Инженерно: `7/10`.
- Продуктово (готовность регистрации end-to-end): `4/10`.

## Что уже сделано хорошо

1. Выбран продовый стек: FastAPI + Postgres + Redis + Celery/Rabbit + Alembic + Docker + CI.
2. Выбран правильный архитектурный поток: `api -> services -> validators -> crud`.
3. Зафиксированы базовые правила: UUID, UTC, soft delete, API versioning.
4. Есть тестовая дисциплина: unit/integration + coverage gate в CI.
5. Правильно расставлены приоритеты безопасности (включая rate-limit).

## Главные проблемы на тот момент

1. Scope расползается (архитектура/infra/auth/тесты параллельно).
2. Много шумных правок и пересборок.
3. Регистрация не была закрыта цельным flow (`verify/resend + отправка`).
4. Часть тестов переусложнялась фейками вместо проверки поведения.

## Правило выполнения

- Закрывать блоки до конца (сначала один DoD, потом следующий блок).
- Не переходить к новым контурам до полного завершения текущего.
- В момент чекпоинта фокус был: `register -> verify-email -> resend-verification-code`.

## Статус

Этот файл сохранен как исторический чекпоинт подхода к дисциплине выполнения.
